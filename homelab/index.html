Détails Techniques de l'Infrastructure

🖥️ Hyperviseur & Matériel

Mon infrastructure physique tourne sur un hyperviseur de type 1, Proxmox VE, exploitant un processeur Intel Core i5-2400 @ 3.10GHz (4 cœurs) avec 12 Go de RAM. Ce nœud PVE me permet de virtualiser mon environnement principal : une grosse machine virtuelle Ubuntu Server à laquelle j'ai alloué 11 Go de RAM pour exécuter tous mes services Docker.

Proxmox VE Intel i5-2400 12GB RAM Ubuntu Server VM

💾 Stockage & Pool MergerFS

Pour la VM, j'utilise un disque OS de 150 Go sur LVM. Pour les données, je fais du "passthrough" de 4 disques physiques (dont 2x 2To et 2x 500Go) directement vers la VM. J'utilise ensuite MergerFS pour regrouper de manière transparente l'espace, créant un pool de 4 To dédié au stockage de mes films et séries, optimisant ainsi l'espace sans complexité RAID.

LVM (150Go) Passthrough Disks MergerFS (4To Pool)

🌐 Réseau, Proxy & Sécurité

L'accès aux services est géré par un Reverse Proxy Nginx pour une résolution DNS locale transparente (noms de domaine internes). Pour l'accès externe de manière sécurisée sans ouvrir de ports sur mon routeur, j'utilise un Cloudflare Tunnel. Cela me garantit un accès HTTPS sécurisé de n'importe où dans le monde pour mes services exposés.

Nginx (Interne) Cloudflare Tunnel HTTPS/SSL

🛡️ Résilience & Sauvegardes (Backups)

Pour prévenir la perte de données, je réalise une sauvegarde complète de la VM une fois par semaine. Ces backups sont externalisés vers le cloud (Google Drive) via l'outil rclone. J'exclus volontairement le point de montage de 4 To (les médias) de ce backup pour ne sauvegarder que la configuration vitale (OS et configs Docker) et ne pas exploser mon quota Cloud.

Full VM Backup rclone Google Drive

📈 Monitoring & Auto-résolution

Le serveur est surveillé en temps réel par Prometheus et Grafana (métriques matérielles/applicatives). Pour aller plus loin, j'utilise n8n (outil d'automatisation). Si Prometheus détecte un conteneur qui crash ou s'emballe, n8n est capable d'interagir avec l'API Docker pour redémarrer automatiquement le service défaillant (Auto-Healing) et m'alerter.
